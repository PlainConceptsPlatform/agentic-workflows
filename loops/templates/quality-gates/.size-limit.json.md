# Ownership: .size-limit.json

Managed by @plainconceptsplatform/workflows. Source: loops/templates/quality-gates/.size-limit.json. Update with `workflows update --force`; consumer edits may be overwritten.

JSON (RFC 8259) does not permit comments, so the ownership header of `.size-limit.json` is documented here. The file tells [size-limit](https://github.com/ai/size-limit) with `@size-limit/file` what to measure: every JavaScript chunk of the web app's static export, `apps/web/out/_next/static/chunks/**/*.js`, brotli-compressed (size-limit's default). The CI runs `size-limit --json` after the web build and `scripts/check-bundle-size.mjs` reads the result.

The first entry is the budgeted total. The budget itself is not here: it is `bundle.limitBytes` in `quality.config.json` (the baseline plus 10%), so this file never carries a `limit` and size-limit itself never fails the build; the mode in `quality.config.json` decides that.

The installer writes the path under the repository's web root (`--web-dir`, or the workflows' `WEB_DIRECTORY`). An app whose export lives elsewhere takes the file over by removing the header paragraph above; `workflows update` then leaves both files alone. Further entries are printed but not gated.
